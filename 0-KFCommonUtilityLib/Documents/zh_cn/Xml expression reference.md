# ${\color{red}问题}$

`CVar` 是一个方便的工具。它允许你向 trigger effect 或 passive effect 传递一个随机值来替代硬编码的数值，还支持简单的计算和比较，从而实现一定复杂度的 XML 逻辑。

但它的能力也就仅此而已了。它对系统其他部分的访问非常有限，而且即使是像"有上限的数值递增"这样简单的操作也需要好几行指令才能完成。另外，它被硬编码为从目标实体获取引用值（`@cvarname`），当你想要从事件发起者那里获取值时就会很麻烦。此外，支持的使用方式是按事件定义的：例如，`ModifyCVar` 不仅接受 `@cvarname`，还接受格式化的 `random`/`tierlist`/`progressionlist` 等；而许多其他事件只接受 `@cvarname`。这种不一致性实在令人恼火。

# ${\color{lightgreen}解决方案初探}$

有了模块系统的支持，我现在可以彻底改变 `CVar` 这套糟烂机制的工作方式了。你们中的一些人可能已经用过 `CVarExpression` 效果，它允许你通过表达式计算出的值来修改 `CVar`。这是一个非常强大的工具（目前仍然有效，并且在新系统中得到了进一步增强），但我们还可以走得更远。

其设计思路是：将 CVar 作为激活模块分支的占位符，同时也是默认值，然后通过应用以下格式的特定模块来劫持数值处理流程：

```xml
<triggered_effect trigger="sometrigger" action="ModifyCVar" cvar="somecvar" operation="set" value="@defaultcvar">
    <mea_module module="ExpressionAsCVar,KFCommonUtilityLib" expr="some complex expression"/>
</triggered_effect>
```

本文档应包含编写你自己的表达式所需的所有信息。

# ${\color{lime}解决方案}$

正如你可能已经猜到的，关键就在于那个 `mea_module` 块。让我们立刻深入探讨。

我将从宏观概述开始。如果你发现某部分难以理解，请继续阅读文档的其余部分然后再回来看，或者查看后面章节中的示例。

## ${\color{gold}模块}$

一个 `module`（在这里指的是 `mea_module`）代表一个包含一组补丁的类，这些补丁会被应用到原始的 `action` 类上。这里的 `mea` 代表 `MinEventAction`，也就是 `action` 类的原生前缀。我们将讨论的模块被设计用来劫持 CVar 取值代码，并运行我们的表达式计算代码来替换原始的 CVar 值。为此，目前创建了以下 3 个模块（使用时需在名称后添加 `,KFCommonUtilityLib`，如上所示）：

### ${\color{yellow}VariableAsCVar}$

最简单的实现，用另一个预定义类型的变量来替换 CVar。变量类型将在后续介绍。

##### 属性：

* `var`：变量。
* `*`：变量可能包含其自身的额外属性。与其他从嵌套元素读取输入的模块不同，`VariableAsCVar` 从当前元素读取这些属性。但你必须将它们放在 `var` 属性之后。

此模块适用于简单的变量替换，例如访问手持物品的元数据或执行随机投掷。

### ${\color{yellow}ExpressionAsCVar}$

标准表达式实现。

##### 属性：

* `expr` 或 `expression`：表达式本体。

##### 子元素：

此模块接受名称为 `var` 的子元素，每个子元素代表一个**唯一**变量的额外属性。使用 `name` 属性来指定要修改的变量，其值为该变量被方括号包围的所有内容。

属性由每个变量自行定义。

### ${\color{yellow}ComplexCondition}$

此模块通过比较两个表达式来过滤当前目标实体，相当于一个条件要求。如果比较结果为 false，该目标会从列表中移除。

老实说，这也可以用 `Requirement` 来实现，但 v2.5 对 `Requirement` 的解析格式做了一些重大修改，所以我打算把 `Requirement` 的模块系统留到 v3.0。

##### 属性：

* `op` 或 `operation`：比较操作，与 `CVarCompare` 相同。作为备忘，支持的操作如下：
  * `=`：`E`、`EQ`、`Equals`
  * `!=`：`NE`、`NEQ`、`NotEquals`
  * `<`：`LT`、`Less`、`LessThan`
  * `>`：`GT`、`Greater`、`GreaterThan`
  * `<=`：`LTE`、`LessOrEqual`、`LessThanOrEqualTo`
  * `>=`：`GTE`、`GreaterOrEqual`、`GreaterThanOrEqualTo`
* `l_val`/`r_val` 或 `l_value`/`r_value`：不等式的左/右侧，作为单个浮点数值。
* `l_var`/`r_val` 或 `l_variable`/`r_variable`：不等式的左/右侧，作为一个变量。
* `l_expr`/`r_expr` 或 `l_expression`/`r_expression`：不等式的左/右侧，作为一个表达式。

##### 子元素：

与 `ExpressionAsCVar` 类似，此模块也接受名称为 `var` 的子元素，并将额外属性留给变量自行定义。此外，它还接受一个 `side` 属性，用于定义该变量应应用于不等式的哪一侧，其支持的值有 `Left`、`Right` 和 `Both`（默认）。

## ${\color{gold}表达式}$

表达式是一组变量与运算符/内置函数的集合，求值后返回一个浮点数值。支持的形式范围从简单的算术运算到组合的逻辑分支。

##### ${\color{yellow}支持的运算符}$

* 数学运算符：`+ - * / % ^`
* 逻辑运算符：`= != < <= > >=`
* `NOT(v)`：如果 v 几乎等于 0 则返回 1，否则返回 0。
* `AND(v1, v2)`：如果 v1 不为 0 则返回 v2，否则返回 v1。
* `OR(v1, v2)`：如果 v1 不为 0 则返回 v1，否则返回 v2。

##### ${\color{yellow}支持的函数}$

* `ROUND(v)`：返回 `v` 四舍五入到最接近的整数值。
* `CEILING(v)`：返回大于等于 `v` 的最小整数值。
* `FLOOR(v)`：返回小于等于 `v` 的最大整数值。
* `LOG(v, p)`：返回指定数字 `v` 以 `p` 为底的对数。
* `LOG(v)`：返回指定数字 `v` 的以 10 为底的对数。
* `MIN(v1, v2)`：返回 `v1` 和 `v2` 中的较小值。
* `MAX(v1, v2)`：返回 `v1` 和 `v2` 中的较大值。
* `IF(cond1, v1[, cond2, v2...], default)`：生成 if-elif-else 分支。你必须提供 N 对条件与值（N >= 1）以及一个默认值，条件从左到右依次检查，返回第一个有效条件的配对值。当 `cond` 的值不为 0 时条件为真。

##### ${\color{yellow}别名定义}$

当一个复杂的变量在表达式中出现多次时，你可以通过以下格式定义一个别名来简化内容：

```
$aliasname1:复杂变量定义;
$aliasname2:复杂变量定义;
[{aliasname1}] + [{aliasname2}]
```

这些都写在 `expression` 属性字符串中。别名定义以 `$` 开头，别名与表达式之间用 `:` 分隔；定义以 `;` 结尾。如上面所示，你可以将它们写在多行以使结构更清晰。

别名定义只能包含一个顶层变量，这意味着你不能写 `$alias:[var1] + [var2]`；要实现这一点，请使用表达式变量代替：`$alias:expr=[var1] + [var2]`。当 `alias1` 被包含在 `alias2` 中时，它必须在 `alias2` 之前定义。

要在表达式中引用别名变量，请写 `[{alias}]`。

### ${\color{orchid}稍等一下……}$

对于七日杀的 XML 来说，这个设计看起来有点奇怪，不是吗？为什么不像这样：把变量定义在它们自己的元素中，让用户指定名称和类型，然后在表达式中使用该名称以避免混淆？

嗯，首要目标是为你的 XML 减负————而不是让它变得臃肿。通常来说，只需在其中放入一些 CVar 和 metadata 并跳过额外属性就足够了，所有这些额外的功能都只是为备不时之需而提供的。

## ${\color{gold}变量}$

变量是游戏数据与表达式之间的桥梁。一般来说，一个变量包含一个值来源和一个默认值：如果从来源获取值失败，则返回默认值。你还可以要求对来源进行显式验证，当验证失败时，整个表达式就不会被求值————此时会使用触发事件本身提供的原始 CVar 值。

### ${\color{yellow}基本属性}$

变量始终包裹在方括号 `[]` 中。变量名的前缀定义了值来源的类型，但它们都共享以下选项：

* 当变量名以 `~` 开头时，它仅为第一个目标求值一次，结果会复用于其余目标。该符号会在解析变量前被移除，但仍然是变量名的一部分。
* 当变量名以 `|` 加一个有效的浮点数值结尾时，该值会被解析为默认值（例如 [var|1.5]）。也支持**变量嵌套**（例如 [var1|[var2]]）。如果未指定，默认为 0。该片段会在解析变量前被移除，但仍然是变量名的一部分。
* `validate`：从额外的 XML 属性中解析，表示此变量需要进行验证。
* `use_self_target`：从额外的 XML 属性中解析，表示在获取实体绑定的值时，应从发起者而非目标获取。默认值为 true，`CVar` 类型变量除外。

变量根据其类型可以是**唯一的**或非唯一的。同一唯一变量在表达式中出现多次时只会被求值一次。

虽然所有变量类型都支持以**嵌套变量**作为默认值，但某些类型也接受将其作为求值过程的一部分。嵌套变量保证在父变量之前被求值，即使当前求值不需要它们的值。

### ${\color{yellow}唯一性}$

同一唯一类型的两个变量，当其完整字符串内容（不区分大小写且忽略空格）不同时，被视为不同的变量。例如，[var]、[~var]、[var|0] 和 [var|1] 被视为不同的变量。

非唯一类型即使内容相同也会生成不同的变量。你可以通过定义别名来强制唯一性。如果一个非唯一类型有额外属性，你必须定义别名才能修改它们。当定义了别名后，解析额外属性时必须使用别名作为变量名。

同一唯一变量在别名定义和主表达式中的多个实例也被视为同一个变量。可以想象变量被嵌套在别名定义中，而别名被嵌套在表达式中，子元素始终在父元素之前被求值。

> 被定义为别名定义中的顶层变量不算作这样的实例。例如，在以下表达式中：
>
> ```
> $alias:var1|[var2];
> [var1|[var2]] + alias + var2
> ```
>
> `var2` 在 3 次出现中仅被求值一次，先于其他变量被求值；然后求值主表达式中的 `[var1|[var2]]`；最后求值 `alias`。
>
> 这通常意味着你也可以使用别名来强制将相同字符串内容视为不同变量（不管其唯一性如何），从而通过额外属性指定不同的行为。

### ${\color{yellow}变量类型}$

正如上文所述，变量的前缀定义了值来源的类型，即变量类型。在本节中，我将介绍 kflib 提供的各种类型。

#### ${\color{lightsalmon}CVar}$

大家钟爱的经典 CVar。

##### 语法：`[@name]`

* `@` 是前缀，`name` 是 CVar 名称。

##### 是否唯一：是

##### 额外属性：无

##### 验证：检查目标实体是否存在且存在对应的CVar。

##### 备注：

* 如果验证被跳过，当目标实体没有设置对应CVar时会返回 0 而非默认值。

#### ${\color{lightsalmon}Metadata}$

类似于 CVar，但绑定在物品上。它可以存储 `float`、`int` 和 `string` 值，但在表达式中使用的必须是 `float` 值。

##### 语法：`[#name]`

* `#` 是前缀，`name` 是元数据名称。

##### 是否唯一：是

##### 额外属性：

* `use_holding_item`：布尔值，表示此变量应查询目标手持物品的元数据，而非分配给事件的物品。

##### 验证：

* 如果 `use_holding_item` 为 true，先检查目标实体是否存在，然后检查手持物品是否不为 null；
* 否则，检查事件分配的物品是否不为 null。

#### ${\color{lightsalmon}LocalCache}$

本地缓存是关联到指定 action 模块的用户自定义值。它允许 mod 制作者在触发效果中计算被动值并将其缓存起来以供后续使用，从而提高性能，并提供与其他系统（特别是 requirement 系统）的通信桥梁——因为在 requirement 中计算被动值是不安全的，最坏情况下游戏会因无限循环而卡死。

希望我能在模块系统的文档中详细讨论细节，目前你可以参考我的 MedicPerk mod。

##### 语法：`[$name(index)]`

* `$` 是前缀，`name` 是缓存名称。
* `index` 是存储缓存值的 action 索引。不设置时使用当前 action 的索引，此时应去掉括号。

##### 是否唯一：是

##### 额外属性：

* `use_holding_item`：布尔值，表示此变量应查询目标手持物品而非分配给事件的物品。

##### 验证：

* 如果 `use_holding_item` 为 true，先检查目标实体是否存在，然后检查手持物品是否不为 null，最后检查 action 是否存在；
* 否则，检查事件分配的物品是否不为 null，然后检查 action 是否存在。

#### ${\color{lightsalmon}Progression}$

根据当前 progression 等级及其对应的数值列表获取值。

##### 语法：`[%progression(num1,num2,...,numN=value1,value2,...,valueN)]`

* `%` 是前缀，`progression` 是 progression 的名称，例如 `%perkGunslinger`。
* `numN` 必须是纯浮点数字。
* `valueN` 可以是浮点数字或嵌套变量。

##### 是否唯一：是

##### 额外属性：无

##### 验证：检查目标是否存在并拥有该 progression。

#### ${\color{lightsalmon}ItemTier}$

根据当前物品的品质等级及其对应的数值列表获取值。

##### 语法：`[tier(num1,num2,...,numN=value1,value2,...,valueN)]`

* `tier(...)` 是标识符。
* `numN` 必须是纯浮点数字。
* `valueN` 可以是浮点数字或嵌套变量。

##### 是否唯一：是

##### 额外属性：

* `use_holding_item`：布尔值，表示此变量应查询目标手持物品的品质，而非分配给事件的物品。

##### 验证：

* 如果 `use_holding_item` 为 true，先检查目标实体是否存在，然后检查手持物品是否不为 null；
* 否则，检查事件分配的物品是否不为 null。

#### ${\color{lightsalmon}PassiveEffect}$

根据指定的标签计算被动值。

##### 语法：`[^passive(tag1,tag2...)]`

* `^` 是前缀，`passive` 是被动效果名称，例如 `^EntityDamage`。
* `tag1,tag2,...` 是要使用的标签。如果不指定标签，应去掉括号，此时使用物品标签。
* 你也可以使用 `+tag1,tag2...` 表示这些标签应与物品标签组合使用。

##### 是否唯一：是

##### 额外属性：

* `use_holding_item`：布尔值，表示在进行被动值计算时应使用目标手持物品，而非分配给事件的物品。
* `use_equipment`：布尔值，表示计算被动值时应包含装备。
* `use_progression`：布尔值，表示计算被动值时应包含 progression。
* `use_buffs`：布尔值，表示计算被动值时应包含 buff。
* `use_challenges`：布尔值，表示计算被动值时应包含挑战。
* `use_mods`：布尔值，表示计算被动值时应包含物品改装件。
* `use_durability`：布尔值，表示计算被动值时应考虑耐久度。
* `tags`：覆盖语法中定义的标签。你可以使用此属性指定标签以简化表达式。

##### 验证：检查目标实体是否存在。

#### ${\color{lightsalmon}RandomInt}$

在指定范围内获取一个随机整数。

##### 语法：`[randomInt(min,max)]`

* `randomInt(...)` 是标识符。
* `min` 是包含的最小值，`max` 是不包含的最大值，两者均接受纯浮点数值或嵌套变量。

##### 是否唯一：否

##### 额外属性：无

##### 验证：无

##### 备注：

* 如果 `min` > `max`，返回默认值。

#### ${\color{lightsalmon}RandomFloat}$

在指定范围内获取一个随机浮点数。

##### 语法：`[randomFloat(min,max)]`

* `randomFloat(...)` 是标识符。
* `min` 是包含的最小值，`max` 是不包含的最大值，两者均接受纯浮点数值或嵌套变量。

##### 是否唯一：否

##### 额外属性：无

##### 验证：无

##### 备注：

* 如果 `min` > `max`，返回默认值。

#### ${\color{lightsalmon}Stat}$

获取实体指定类型的属性值。

##### 语法：`[stat(stat_type,value_type)]`

* `stat(...,...)` 是标识符。
* `stat_type` 是实体属性类型。支持的值：
  * Health（生命值）
  * Stamina（体力值）
  * Food（饱食度）
  * Water（水分值）
* `value_type` 是要获取的实际值类型。支持的值：
  * Current（当前值）
  * CurrentPerc（当前值百分比）
  * Max（最大值）
  * MaxModifier（最大值修正）
  * ModifiedMax（修正后的最大值）
  * ModifiedMaxPerc（修正后的最大值百分比）

##### 是否唯一：是

##### 额外属性：无

##### 验证：检查目标实体是否存在并拥有指定的属性。

#### ${\color{lightsalmon}Expression}$

将整个表达式作为变量嵌套。

##### 语法：`[expr=expression_body]`

* `expr=` 是前缀。
* `expression_body` 是实际的表达式。

##### 是否唯一：是

##### 额外属性：无

##### 验证：无

##### 备注：

* 嵌套表达式变量与主表达式共享变量集合。

#### ${\color{lightsalmon}TargetIndex}$

获取当前目标的索引。

##### 语法：`[targetIndex]`

##### 是否唯一：是

##### 额外属性：无

##### 验证：无

#### ${\color{lightsalmon}TargetCount}$

获取目标的总数量。

##### 语法：`[targetCount]`

##### 是否唯一：是

##### 额外属性：无

##### 验证：无

#### ${\color{lightsalmon}Distance}$

获取从发起者到目标的距离。

##### 语法：`[distance]`

##### 是否唯一：是

##### 额外属性：无

##### 验证：检查发起者是否存在。

#### ${\color{lightsalmon}HPDamage}$

获取上次攻击造成的生命值伤害。

##### 语法：`[hpDamage]`
